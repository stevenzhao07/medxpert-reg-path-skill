## 这是什么？

一个适配 Claude Code / Codex 等 Agent 环境的医疗器械注册专业Skill。

输入一个产品的基本信息和目标市场，AI Agent就能像做了十年注册的老炮一样，输出：

- ✅ **风险分类结论** + 法规依据
- ✅ **注册路径判定**（510(k) / PMA / De Novo / CE-MDR / NMPA）
- ✅ **临床要求**（免临床 / 同品种比对 / 临床试验）
- ✅ **发补风险预判**（P0必退 / P1补正 / P2优化 三级清单）
- ✅ **周期与费用估算**（区间值，带关键节点）

## 核心方法论 · LGD三律

> 这不是普通的AI助手——这是 **LGD（有籍有证有门禁）体系** 的第一个落地Skill。

| 律 | 这个Skill怎么做到的 |
|---|-------------------|
| **有籍** | 每条路径判定都挂法规依据，不瞎编 |
| **有证** | 从产品信息→分类→路径，一步步推导，不跳步 |
| **有门禁** | 6条P0禁令 + 6轴自评分 + 提交前检查清单 |

别的AI：你问它510(k)路径，它直接给你个答案——对不对全靠它自觉。

我们这个：**拿不准就标"待确认"，P0级错误直接拦截，输出前自己先检查一遍。**

## 为什么需要它？

AI做医疗器械注册最大的问题不是"做不出来"，是**瞎编**——编法规条款、编分类结论、编费用数字。

MedXpert Reg Path Skill做的事情，是把注册专家的判断力变成**硬门禁规则**：

| 门禁 | 说明 |
|------|------|
| **有籍** | 每一条结论必须挂具体法规条款，不许瞎编 |
| **有证** | 每一个判定必须有证据链：产品特性 → 分类规则 → 路径结论 |
| **有门禁** | P0级错误直接拦截，输出前必须过6轴自评分 |

## 核心特性

- 🚦 **P0/P1/P2三级发补风险清单**：提交前自查，降低发补概率
- ✅ **输出前6轴自评分**：低于3分自动返工，不交付烂结论
- 📋 **完整工作流**：信息收集 → 分类判定 → 路径选择 → 临床要求 → 风险预判 → 周期估算
- 🔍 **置信度标注**：确定 / 高概率 / 待确认，不硬下结论
- 🛡️ **硬门禁规则**：6条P0级禁令，违反任何一条输出作废

## 适合谁用？

- 医疗器械公司的注册专员
- 国际业务负责人做市场进入决策
- 创业者判断新产品的注册成本和周期
- 咨询公司快速响应客户咨询

## 不适合什么？

- ❌ 药品注册 / 化妆品注册（不是本Skill范围）
- ❌ 质量体系文件编写（GMP/ISO 13485文件不在此Skill）
- ❌ 临床实验方案设计（只判定需不需要临床，不设计方案）
- ❌ 申报资料逐字代写（只出清单和要点，不代写全文）

## 与同类Skill的区别

| 对比项 | 通用AI助手 | 我们的Skill |
|--------|-----------|------------|
| 法规准确性 | 经常编条款号 | 每条挂法规依据，不确定标"待确认" |
| 分类判定 | 模糊"大概二类" | 明确结论 + 边界情况列两种可能 |
| 发补风险 | 泛泛而谈 | P0/P1/P2分级，每条配自查要点 |
| 输出质量 | 看模型心情 | 6轴自评分门禁，不过关自动返工 |
| 置信度 | 从不标注 | 每个结论都标置信度 |

## 为什么做这个？

做医疗器械注册这些年，最头疼的就是AI瞎编法规——问个510(k)路径，它能给你编出不存在的条款号。

这个Skill就是想给AI装上一个"老实人"的大脑：有依据的就说有依据，拿不准的就标"待确认"，不确定的绝不硬下结论。

它是 **LGD（有籍有证有门禁）体系** 在医疗器械注册领域的第一个落地实例：
- **有籍**：每条结论挂法规出处，不瞎编
- **有证**：每个判定有证据链，不跳步
- **有门禁**：输出前过6轴自检，P0级错误直接拦截

如果你也是做医械注册的，欢迎一起把它变得更准。
